# 分析是如何工作的

[English](algorithms.md) · [Русский](algorithms.ru.md) · **简体中文**

从一根下载回来的K线到屏幕上的一条建议，中间每一个算法的概览。目的是让整条管线可读，而不是替代代码：
每一节都点明负责它的包。确定性策略的深入说明见 [strategies.md](strategies.md)，回放引擎见
[backtesting.md](backtesting.md)。

```
K线 ─► 指标 ─► 形态 ─► 市场结构 ─► 支撑阻力 ─► 背离 ─► 市场状态
                                                        │
                          先按周期分别计算，再做聚合 ────┘
                                                        ▼
                    特征快照 + 新闻 + 历史战绩 + 过去的相似案例
                            │                    │
                    确定性投票                压缩快照 ─► LLM ─► 校验
                            └────────► 风险引擎 ◄────────┘
                                            ▼
                                          建议
```

LLM 之前的一切都是确定性的：相同的K线进去，相同的数字出来，并有单元测试覆盖。模型只负责解读这些
数字，从不自己产出任何一个。

---

## 1. 指标

`internal/analysis/indicators` —— 约 25 个经典指标，全部只用已收盘K线计算，且每个都返回完整序列，
这样能读出随时间的变化，而不只是最后一个值。

| 类别 | 计算内容 |
|---|---|
| 趋势 | SMA/EMA/WMA（多个长度）、MACD、带 +DI/−DI 的 ADX、Aroon、均线斜率 |
| 动量 | RSI、随机指标、Stochastic RSI、CCI、Williams %R、ROC、Momentum |
| 波动率 | ATR 及其占价格的百分比、相对自身历史的分位数、布林带及带宽、肯特纳通道、已实现波动率 |
| 成交量 | OBV、MFI、CMF、滚动 VWAP 与按日锚定 VWAP、相对成交量 |
| 统计 | 分位数、斜率、标准差、均值——上面这些规则赖以构建的基础函数 |

ATR 的分位数比 ATR 本身更重要：“波动大”只有相对于该资产平常的表现才有意义。

## 2. 形态

`internal/analysis/patterns` —— 约 45 种K线形态（吞没、锤子、星线、孕线、光头光脚……）与 20 种图表
形态（双顶双底、头肩、三角形、楔形、旗形、通道、突破及其回踩）。

每一次命中都带有方向、强度以及**以K线计的年龄**。正是年龄让形态可用：三根K线前的突破与四十根K线前
的同一个突破是两个不同的事实，只有新鲜的那个才被允许改变市场状态。

## 3. 市场结构

`internal/analysis/marketstructure` —— 半宽为 3 根K线的分形枢轴，标注 HH/HL/LH/LL，并由此得出状态
（看涨、看跌、区间、过渡）以及 **BOS**（结构突破）与 **CHoCH**（性质转变）事件。

**防重绘规则：** 第 *i* 根K线上的枢轴，只有在其后 `depth` 根K线收盘之后才会被确认。一个之后还会被
重画的摆动点还不算摆动点——这与保证回测诚实的是同一套纪律。

## 4. 支撑与阻力

`internal/analysis/supportresistance` —— 来自摆动点、日历高低点与整数关口的候选价格，彼此相差不超过
0.35 % 时聚为一簇。簇的强度随触碰次数增加、随年龄衰减；最强的八个位置保留下来，并单独标出当前价格
下方最近的支撑与上方最近的阻力——交易计划真正必须尊重的就是这两个。

## 5. 背离

`internal/analysis/divergences` —— 价格枢轴与 RSI、MACD、OBV 之间的常规背离与隐藏背离。枢轴对只在
120 根K线的回看窗口内比较，间隔至少 4 根、最多 60 根，且两者价格差需超过 0.15 %。这三个过滤条件之所以
存在，是因为没有它们的话到处都能“找到”背离。

## 6. 市场状态

`internal/analysis/regime` —— 纯规则、不涉及模型，正因如此它才能作为与 LLM 对比的基准。

```
ADX ≥ 40 且 +DI > −DI  →  强上升趋势        ADX ≥ 40 且 −DI > +DI  →  强下降趋势
ADX ≥ 25 且 +DI > −DI  →  弱上升趋势        ADX ≥ 25 且 −DI > +DI  →  弱下降趋势
ADX < 20               →  区间              新鲜的突破形态          →  突破
```

当 ADX 无话可说时，市场结构可以把区间提升为带方向的判断。在主标签之上，分类器还会附加标签——高/低
波动、强/弱动量、超买/超卖、放量或缩量、临近支撑或阻力、挤压、区间扩张——以及由 ADX 与 ATR 推导出的
置信度。

同一个包还计算**确定性评分**：趋势、动量、形态与波动风险各自落在 [−1, 1]，再合成多空分解。这就是界面
上显示在模型意见旁边的那个数字。

## 7. 新闻：只是约束，从不指示方向

`internal/news`。RSS/Atom 订阅与 Bybit 公告以条件 GET、响应大小限制和 SSRF 防护抓取，随后归一化、
去重并聚类：标题之间用词法相似度比较（词元 Jaccard 加上二元组 Dice），并受“受保护词元”约束，因此两条
新闻绝不会仅因提到同一资产就被合并。关键词规则给每个聚类归类（黑客、漏洞利用、下架、暂停交易、上币、
监管……）并带有各自的置信度；重要性得分则由类别、来源优先级、新鲜度以及有多少独立来源报道共同决定。

**一条新闻永远不会为某个方向背书。** 市场对事件的反应并不确定，因此一个新鲜的关键事件只能*限制敞口*
——压低杠杆，或者直接否决入场。观察到的反应历史（过去类似事件之后价格实际怎么走）是提供给模型和统计
的上下文，而不是方向生成器。

## 8. 特征快照

`internal/analysis/features` —— 每个周期独立分析，然后聚合：跨周期的趋势一致性评分、市场总览、数据
质量（`ok`、`degraded`、`unusable`，取决于缺失多少以及有多陈旧），以及用于相似度检索的归一化
**特征向量**。

`internal/history` 通过这些向量的余弦相似度（重新缩放到 [0, 1]）寻找**过去的相似案例**，同一交易对
额外获得 5 % 加成——过去的 BTC 情形对 BTC 的说明力，强于一个同样相似的 SOL 情形。只考虑严格早于当前
分析时刻的运行记录，而且每个案例带的是它真实的结果，不是它的预测。

## 9. 确定性投票

`internal/analysis/strategies` —— 这套策略在*不用*模型的情况下，对同一份快照、在同一个周期内给出自己的
结论，并与模型的结论并排保存：于是“LLM 对比规则”可以在同一段历史上得到回答。

约十六个方向性策略（综合评分、更高周期趋势、唐奇安突破、Supertrend、Connors RSI(2) 回归、状态动量、
EMA 趋势、ADX/DI……）以 [0, 1] 的强度乘以各自权重投多头或空头票。十个过滤器（成本下限、过度延伸防护、
趋势与大盘闸门、相对强度、反向关口、周期冲突、波动率防护、状态防护、关键新闻）投*反对*票，被标记为
**硬否决**的过滤器则无视权重直接阻止入场。只有当方向性净优势同时超过阈值（默认 1.8）与过滤器总权重
时才会开仓。权重可以随市场状态自适应：趋势存在时顺势观点权重更高，区间内则轮到均值回归观点。

随项目提供的权重，是在 12 个资产、三个周期、两个独立时期共约 47 600 笔模拟交易上拟合出来的——那仍然
只是一个市场和五年，因此它是起点而非真理。参见 [strategies.md](strategies.md)。

## 10. 模型层

`internal/llm` —— 完整快照始终被持久化，但只有它的**压缩投影**会送给模型，因为上下文是有限的。回答
必须满足严格的模式约束：枚举、取值范围、止盈止损位于入场价的正确一侧、平仓比例之和正确、仓位与杠杆
处于配置范围之内。所有发现的问题会被一并收集，好让唯一一次修复重试能同时处理它们；如果修复仍然失败，
该回答会作为推理错误保存，并且不产生任何建议。模型缺失或不可达并不会拖住其他任何环节——数据采集与
全部技术分析照常运行。

## 11. 风险引擎

`internal/risk` —— 确定性的，并且拥有最终决定权。它根据波动率及其分位数、止损距离、市场状态、周期一致
性、附近的反向关口、声明的置信度与数据质量，重新计算允许的杠杆与仓位规模，再把模型给出的数字夹到这个
范围内。界面会同时展示两个数字：模型请求的，以及实际被允许的。

其中两条规则承担了大部分作用：

* **一次止损不得抹掉整个仓位。** 杠杆为 L、止损距离为 D 个百分点时，触发止损大约损失保证金的 L·D
  个百分点；这个乘积被限制在 35 %。
* **仓位规模由单笔风险决定。** “一次止损最多损失本金的 R %”，结合杠杆与止损距离，直接得出仓位比例，
  于是平静的资产与剧烈波动的资产承担相同的风险，而不是相同的规模。

新鲜的关键新闻事件会在此之上叠加一个与方向无关的杠杆上限；当技术性波动本就偏高时，这个上限更严格。

## 12. 结果判定与统计

`internal/recommendations/outcomes.go` 与 `internal/history`。一条建议发出二十四小时后，其市场结果被
最终判定——哪个价位先被触及、最大有利与最大不利偏移，以及是否因为两个价位在同一根K线内都被触及而属于
模糊案例。三类事实被严格区分：

| 类别 | 含义 |
|---|---|
| `model_prediction` | 模型说了什么 |
| `market_outcome` | 市场随后做了什么 |
| `user_trade_outcome` | 你实际实现了什么 |

只有后两类算证据。永远不会告诉模型“你说了 LONG，所以 LONG 是对的”。预测不可变；决定与结果存放在各自
的表中。统计页面据此得出胜率、盈亏比、期望值、MFE/MAE、回撤与持仓时间——外加**校准度**，它追问关于
声明置信度唯一重要的问题：模型说 90 % 的时候，它是否真的有 90 % 的正确率？

## 13. 历史回放

`internal/backtesting` —— 同一条分析路径，只不过由已存K线驱动。在模拟时刻 T，它只收到收盘时间不晚于 T
的K线，持仓从下一根K线开始模拟，新闻、历史战绩与相似案例也按同样方式截断，包括结果判定在内。这一点由
回归测试保证：给数据接上一段截然不同的未来，不得改变任何更早的交易。手续费、资金费、滑点、部分成交、
强平与维持保证金全部纳入模拟。细节见 [backtesting.md](backtesting.md)。
